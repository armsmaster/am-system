# am-system

Система контроля позиции управляющей компании паевых фондов.

- Архитектура: [docs/architecture.md](docs/architecture.md)
- Решения по предметной области: [docs/decisions.md](docs/decisions.md)
- Открытые вопросы: [docs/open-questions.md](docs/open-questions.md)
- Дизайн шагов: [docs/design/](docs/design/)
- Блог о системе для инженеров и финансистов: [docs/blog/](docs/blog/README.md)

## Что нужно установить

- Docker Desktop (или Docker Engine с compose)
- [uv](https://docs.astral.sh/uv/) — окружение Python 3.13
- Node.js 24 и npm
- GNU Make (в Git Bash на Windows есть)

## Запуск

```bash
cp .env.example .env   # необязательно: без .env берутся те же значения
make up
```

Приложение: <http://localhost:8080>. Первый запуск дольше: Keycloak
импортирует realm, образы собираются.

Пользователи для разработки (только локально, задаются в
`infra/keycloak/realms/am-realm.json`):

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin-dev` | администратор |
| `trader` | `trader-dev` | трейдинг |
| `ops` | `ops-dev` | сопровождение |
| `risk` | `risk-dev` | риск-менеджмент |

Если realm Keycloak менялся, пересоздайте данные: `make reset && make up`.
Keycloak импортирует realm только в пустую базу. Чтобы не терять данные,
допишите недостающие роли, клиентов и пользователей в работающий Keycloak:
`make keycloak-sync` покажет, чего не хватает, а
`uv run python scripts/keycloak_sync.py --apply` добавит. Существующее скрипт
не меняет.

Шлюз следит за файлами маршрутов в `infra/traefik/dynamic/`, но на Docker
Desktop под Windows события изменения файлов до контейнера не доходят.
После правки маршрутов перезапустите шлюз: `docker compose restart gateway`.

Консоль Keycloak: <http://localhost:8080/auth/admin>
(`kcadmin` / `kcadmin-dev`). Панель шлюза: <http://localhost:8081>.

## Развёртывание на виртуальной машине

Режим разработки держит в репозитории всё для запуска одной командой: адрес
`localhost`, пароли вида `admin-dev`, секреты служебных учётных записей. На
машине в интернете их быть не должно. Режим ВМ включается файлом `.env`,
который собирает `scripts/vm_config.py`:

| Что | Разработка | ВМ |
|---|---|---|
| адрес | `http://localhost:8080` | `https://<домен>` |
| HTTPS | нет | Caddy, сертификат Let's Encrypt (профиль `tls`) |
| шлюз | на всех адресах машины | только `127.0.0.1`, снаружи — через Caddy |
| Keycloak | `start-dev` | `start`, рабочий режим |
| пользователи | `admin`, `trader`, `ops`, `risk` с паролями `*-dev` | один `admin` с временным паролем |
| пароли и секреты | `*-dev` из репозитория | случайные, только в `.env` на машине |

Что нужно: ВМ с Ubuntu 24.04 — от 4 vCPU, 8 ГБ памяти и 40 ГБ диска; домен,
который указывает на её адрес; в файрволе облака открыты порты 22, 80 и 443.

1. Установите Docker Engine с плагином compose по инструкции Docker для Ubuntu
   (docs.docker.com/engine/install/ubuntu), затем git:

   ```bash
   sudo apt-get install -y git
   ```

2. Скачайте код:

   ```bash
   git clone https://github.com/armsmaster/am-system.git && cd am-system
   ```

3. Соберите настройки — домен и адрес, на который Let's Encrypt пришлёт
   напоминание о сертификате. Хватит системного `python3`:

   ```bash
   python3 scripts/vm_config.py --domain am.example.ru --email ops@example.ru
   ```

   Скрипт пишет `.env` и `infra/keycloak/realm-vm/am-realm.json` — оба не
   в git — и печатает временный пароль пользователя `admin`. Сохраните его:
   больше он нигде не показывается.

4. Запустите:

   ```bash
   docker compose up -d --build
   ```

   Первый запуск — 10–20 минут: собираются образы, Keycloak импортирует
   realm, Caddy получает сертификат.

5. Откройте `https://am.example.ru`, войдите как `admin` с временным паролем —
   Keycloak попросит сменить его. Пользователей заведите в консоли Keycloak
   `https://am.example.ru/auth/admin` (`kcadmin`, пароль —
   `KEYCLOAK_ADMIN_PASSWORD` в `.env`), доступ к фондам выдайте в разделе
   «Администрирование → Доступы».

Секреты скриптов цен, сделок и выписок — `PRICE_FEED_SECRET`,
`TRADE_FEED_SECRET`, `STATEMENT_FEED_SECRET` в `.env`: передайте их авторам
скриптов.

**Пароли собираются один раз.** База и Keycloak запоминают их при первом
запуске. Скрипт не перезапишет `.env` без `--force`: новые пароли не подойдут
к уже созданной базе. Пересобирать можно только до первого запуска или после
`docker compose down -v`, которая удаляет все данные.

**Резервные копии.** Данные — в томе Docker `postgres-data` на диске машины.
Как минимум — ежедневный дамп по cron с копированием за пределы машины:

```bash
docker compose exec -T postgres pg_dumpall -U postgres | gzip > backup-$(date +%F).sql.gz
```

Чего режим ВМ не делает: не закрывает консоль Keycloak `/auth/admin` от
интернета и не включает OTP — это решения о доступе пользователей (вопрос 54
в [open-questions.md](docs/open-questions.md)). Управляемый PostgreSQL
провайдера вместо контейнера — вопрос 53.

## Разработка фронтенда без пересборки образов

Окружение (`make up`) должно быть запущено — из него берутся Keycloak и API.

```bash
cd frontend
npm run dev:admin   # администрирование на :3001
npm run dev:audit   # журнал на :3002
npm run dev:refdata # справочник на :3003
npm run dev:marketdata # цены на :3004
npm run dev:booking    # сделки на :3005
npm run dev:reconciliation # сверка на :3006
npm run dev:limits     # лимиты на :3007
npm run dev:shell   # shell на :3000
```

Открыть <http://localhost:3000>.

## Проверки

```bash
make check       # линтеры, типы, все тесты с покрытием — как в CI
make test-unit   # быстрые тесты бэкенда без контейнеров
```

Покрытие тестами — 100% строк и ветвей; CI не пропускает изменения ниже
порога. Из покрытия исключены только точки входа фронтенда
(`index.ts`, `bootstrap.tsx`) — это связка со сборщиком.

## Структура

```
compose.yaml        локальное окружение
infra/              Postgres (init), Keycloak (realm), Traefik (маршруты)
libs/am-common/     общая библиотека: настройки, токены, БД, outbox, события, миграции
libs/am-quant/      расчёты по облигациям: доходность, метрики, спреды флоатеров и линкеров
services/Dockerfile общий образ Python-сервисов
services/portfolio/ портфели, фонды, счета, доступы
services/audit/     журнал действий пользователей
services/refdata/   справочник: бумаги из MOEX ISS, версии, эмитенты, рейтинги, классификаторы, календарь
services/booking/   сделки с версиями, операции фонда и переводы, позиции по двум датам с лотами FIFO,
                    деньги, лестница расчётов, пересчёт задним числом, импорт сделок пакетом,
                    оценка позиций и финансовый результат с разложением, СЧА и стоимость пая,
                    комиссии от СЧА с ежедневным начислением и выплатой за период,
                    РЕПО с НКЦ: части, проценты, передача дохода, компенсационные взносы,
                    прогноз купонов флоатеров в лестнице
services/marketdata/ цены от скрипта и из ISS, OHLC и DEMA, ручные цены, НКД и номинал на дату,
                    ставки, доходность и спред на момент цены
services/reconciliation/ выписки брокера и банка, сверка сделок, движений и остатков денег,
                    принятые расхождения, которые ждут пары
services/limits/    наборы лимитов инвестиционной политики с версиями, использование лимитов
                    фонда за день: плечо, дюрация, доли, допустимые инструменты, условия покупки
frontend/
  packages/platform/  контракт shell ↔ микрофронтенды, API-клиент
  packages/ui/        общие помощники интерфейса: загрузка данных, действия, ошибки
  packages/shell/     оболочка: вход, навигация, общие стили
  packages/mfe-admin/ администрирование: портфели, счета, доступы
  packages/mfe-audit/ журнал действий
  packages/mfe-refdata/ справочник: бумаги, эмитенты, рейтинги, классификаторы, календарь
  packages/mfe-marketdata/ цены: обзор с разбросом, карточка с графиком и расчётом, правило, лента скрипта
  packages/mfe-booking/ сделки: ввод с подсказкой НКД, карточка с версиями, позиции по двум датам,
                    операции фонда, лестница расчётов с дефицитами, импорт сделок из файла,
                    оценка и результат за период, СЧА с составом и ставками комиссий,
                    ввод РЕПО и взносов, открытые РЕПО в позициях
  packages/mfe-reconciliation/ сверка фонда за день по счетам, принятие расхождений,
                    подтверждение сошедшихся сделок, выписки: история и ввод вручную
  packages/mfe-limits/ лимиты: использование за день с подробностями, набор лимитов
                    с версиями и описанием словами
docs/               архитектура, решения, вопросы, дизайн шагов, спецификации для скриптов, блог
```
