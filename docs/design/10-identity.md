# Вход и пользователи

**Статус.** Сделано 25.11.2026, решение 170 — в [../decisions.md](../decisions.md).
Своя страница входа с «Запомнить меня», первый вход с временным паролем,
приглашение по ссылке, смена своего пароля, вкладка «Пользователи» в
администрировании. Пользователи и роли по-прежнему живут в Keycloak.

## Зачем

Раньше вход шёл через страницу Keycloak: браузер уезжал на `/auth/...`,
пользователь видел чужой интерфейс на английском и возвращался обратно. Новых
пользователей заводили в консоли Keycloak — это отдельная программа с сотней
настроек, где легко ошибиться.

Теперь:

- вход — на странице приложения, в его оформлении и на русском;
- администратор заводит пользователя в самом приложении и отдаёт ему ссылку;
- по ссылке пользователь сам задаёт пароль и сразу входит — пароль никто,
  кроме него, не знает.

## Как устроено

```
браузер ──► /api/identity ──► сервис identity ──► Keycloak
   ▲            (шлюз)          │  вход: grant password от клиента am-web
   │                            │  пользователи: Admin API под am-identity
   └── access token в памяти    └── своя схема: ссылки, последний вход, outbox
       refresh token в cookie
```

Сервис `identity` — посредник: пароль проверяет Keycloak, сервис только
передаёт его и раскладывает ответ.

- **Access token** (5 минут) приходит в теле ответа. Страница держит его
  в памяти и отдаёт микрофронтендам через сессию — как раньше.
- **Refresh token** сервис кладёт в cookie `am_refresh`:
  - `HttpOnly` — скрипты страницы его не видят, даже если на страницу
    попадёт чужой код;
  - `SameSite=Strict` — чужой сайт не отправит его вместе со своим запросом;
  - путь `/api/identity/public/auth` — браузер шлёт его только на адреса входа,
    а не с каждым запросом к API;
  - `Secure` — когда приложение открыто по HTTPS.

## Сценарии

### Вход

Логин, пароль, галочка «Запомнить меня» → `POST /public/auth/login`. Сервис
спрашивает Keycloak, при успехе отдаёт токен и ставит cookie, записывает время
входа и событие в журнал. Страница остаётся на том адресе, куда шёл пользователь:
открыл ссылку на позиции — после входа видит позиции.

### «Запомнить меня»

| | С галочкой | Без галочки |
|---|---|---|
| Сессия Keycloak | офлайн | обычная |
| Без активности живёт | 7 дней | 30 минут |
| Не дольше | 30 дней | 10 часов |
| Cookie | со сроком — переживает закрытие браузера | до закрытия браузера |

Сроки — те же, что в решении 162. Keycloak применяет свои настройки
«Remember me» только на своей странице, поэтому «запомненный» вход —
офлайн-сессия (scope `offline_access`) со сроками из настроек realm.

Пример. Трейдер вошёл с галочкой в понедельник и закрыл браузер. Во вторник
открыл приложение — сразу внутри: страница по cookie получила новый токен.
Не заходил три недели — с последнего входа прошло больше 7 дней, сессия
закончилась, будет страница входа. Заходит каждый день — через 30 дней с
первого входа всё равно попросят пароль.

Антипример. Галочка на общем компьютере в переговорной: следующий человек
откроет приложение под чужим именем. Поэтому под галочкой — предупреждение.

### Сессия во время работы

Перед каждым запросом к API сессия проверяет токен: до истечения меньше 30
секунд — берёт новый (`POST /public/auth/refresh` с cookie). Десять запросов
одновременно ждут одно обновление. Keycloak отказал — сессия закончилась или
пользователя заблокировали — страница перезагружается и показывает вход.
Сервис недоступен — страница остаётся, запрос повторится.

### Выход

`POST /public/auth/logout`: сервис закрывает сессию в Keycloak и удаляет cookie.
Keycloak недоступен — cookie всё равно удаляется.

### Первый вход с временным паролем

Временный пароль бывает у администратора ВМ (его выдаёт `scripts/vm_config.py`)
и у пользователей, заведённых в консоли Keycloak. Keycloak отвечает «задайте
пароль» только тем, кто ввёл временный пароль верно, — тогда страница сразу
показывает форму «Задайте свой пароль». Сервис ставит новый пароль, снимает
обязательные действия и входит.

### Приглашение

1. Администратор: «Новый пользователь» — логин, имя, фамилия, email по желанию,
   роли, срок ссылки 1, 3 или 7 дней.
2. Система заводит пользователя в Keycloak без пароля и показывает ссылку
   `https://<адрес>/invite/<секрет>` с кнопкой «Скопировать».
3. Пользователь открывает ссылку, видит своё имя и логин, задаёт пароль — и
   сразу внутри.

Свойства ссылки:

- **одноразовая** — второй раз по ней пароль не задать;
- **одна действующая** — новая ссылка отменяет прежние;
- **в базе только отпечаток** (SHA-256) секрета: кто прочитает базу, ссылку
  не восстановит. Поэтому ссылку видно один раз, при выдаче;
- **понятные отказы**: «уже использована», «заменена новой», «срок истёк»,
  «не найдена».

### Забытый пароль

Почты в системе нет, поэтому восстановление — через администратора: «⋯ →
Новая ссылка для входа». Пока по ссылке не задан новый пароль, старый
действует — ссылка никого не выключает.

### Смена своего пароля

Меню пользователя → «Сменить пароль»: текущий, новый, повтор. Сервис проверяет
текущий пароль входом в Keycloak и сразу закрывает эту проверочную сессию.

### Правила пароля

Не короче 10 символов и не совпадает с логином. Страница отмечает правила по
мере ввода, сервис проверяет то же самое. В realm для ВМ — ещё и политика
паролей Keycloak (`length(10) and notUsername`): она действует, если пароль
меняют в консоли Keycloak. В realm разработки политики нет — пароли
пользователей разработки короче, их знает README.

### Блокировка

«⋯ → Заблокировать»: Keycloak запрещает вход и завершает все сессии
пользователя, «запомненные» тоже, — следующее обновление токена получит отказ.
Уже выданный access token доживает свои минуты (не больше 5). Себя заблокировать
и снять с себя роль администратора нельзя: иначе можно остаться без
администратора.

## Статус пользователя

| Статус | Когда |
|---|---|
| активен | входил хотя бы раз или ссылки не было (заведён в Keycloak) |
| ждёт первого входа до … | есть открытая ссылка, входов ещё не было |
| ссылка истекла | ссылка не использована, срок прошёл — выдайте новую |
| заблокирован | вход запрещён |

«Последний вход» — время входа по паролю или по ссылке. Обновление токена —
не вход: человек с «Запомнить меня» может работать каждый день с одним входом.

## API

| Метод | Путь | Кто | Что |
|---|---|---|---|
| POST | `/public/auth/login` | все | вход: `{username, password, remember}` |
| POST | `/public/auth/refresh` | по cookie | новый access token |
| POST | `/public/auth/logout` | по cookie | выход |
| POST | `/public/auth/first-login` | все | временный пароль → свой и вход |
| GET | `/public/invites/{секрет}` | все | чья ссылка и до когда действует |
| POST | `/public/invites/{секрет}/accept` | все | пароль по ссылке и вход |
| POST | `/me/password` | вошедший | смена своего пароля |
| GET | `/users` | админ | люди: роли, статус, последний вход |
| POST | `/users` | админ | новый пользователь и ссылка |
| PUT | `/users/{id}/roles` | админ | роли |
| PUT | `/users/{id}/enabled` | админ | блокировка и разблокировка |
| POST | `/users/{id}/invite` | админ | новая ссылка |

Вход, сессия, первый вход и приглашение отвечают `{access_token, expires_in,
user: {id, username, display_name, roles}}`. Отказ — как у остальных сервисов:
`{"detail": {"code", "message"}}`, сообщение — для пользователя.

| Код | HTTP | Когда |
|---|---|---|
| `invalid_credentials` | 401 | неверный логин или пароль |
| `account_disabled` | 403 | пользователь заблокирован |
| `account_locked` | 423 | Keycloak временно закрыл вход после неудачных попыток |
| `password_change_required` | 409 | временный пароль верный — задайте свой |
| `no_session`, `session_expired` | 401 | cookie нет или сессия закончилась |
| `weak_password`, `same_password`, `wrong_password` | 422 | правила пароля |
| `invite_not_found` | 404 | ссылки нет |
| `invite_used`, `invite_revoked`, `invite_expired` | 410 | ссылка закрыта |
| `username_taken`, `email_taken` | 409 | логин или email заняты |
| `self_admin`, `self_block`, `user_blocked` | 409 | защита от ошибок администратора |
| `login_not_configured`, `keycloak_unavailable` | 503 | Keycloak не настроен или не отвечает |

## Данные

Схема `identity`:

- `invitation` — ссылки: пользователь, отпечаток секрета, срок, кто выдал,
  когда использована или отменена;
- `last_login` — время последнего входа;
- `outbox` — события для журнала.

События (в журнале — «было → стало»): `user.created`, `user.invited`,
`user.password_set`, `user.password_changed`, `user.logged_in`,
`user.roles_changed`, `user.blocked`, `user.unblocked`.

## Keycloak

| Настройка | Значение | Зачем |
|---|---|---|
| `am-web`: Direct access grants | включено | вход по паролю через сервис |
| Офлайн-сессия | 7 дней без активности, не дольше 30 | «Запомнить меня» |
| Обязательное действие Verify Profile | выключено | профиль требует email, а он необязателен; страниц Keycloak пользователь не видит |
| Клиент `am-identity` | служебная учётная запись: `view-users`, `query-users`, `manage-users` | заводить пользователей, роли, пароли, завершать сессии |
| Политика паролей (только ВМ) | `length(10) and notUsername` | те же правила в консоли Keycloak |

`am-identity` не читает настройки realm: роли берёт у каждого пользователя,
а роль для назначения — из списка доступных этому пользователю.

Работающий Keycloak разработки донастраивает `make keycloak-sync` (с `--apply`):
скрипт приводит к realm и эти настройки. На ВМ — см. README.

Консоль Keycloak `/auth/admin` остаётся: там администратор системы видит
сессии, журнал входов Keycloak и всё, чего нет в приложении.

## Чего нет

- Входа через почту и восстановления пароля без администратора: почты нет.
- Второго фактора (OTP) — вопрос 54 в [../open-questions.md](../open-questions.md).
- Правки имени и email в приложении — в консоли Keycloak.
- Удаления пользователей: блокировка сохраняет его действия в журнале понятными.
