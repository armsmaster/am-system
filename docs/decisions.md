# Решения по предметной области

Журнал ответов пользователя на уточняющие вопросы. Номер — номер вопроса
в обсуждении. При изменении решения старая запись не удаляется, а
дополняется новой с датой.

## Процессы и MVP (2026-10-24)

| № | Решение |
|---|---|
| 42 | Операция выдачи или погашения паёв сразу меняет количество паёв и создаёт требование (выдача) или обязательство (погашение). Когда расчёт прошёл, сопровождение отмечает это вручную — тогда меняются деньги. |
| 43 | Вознаграждение начисляется ежедневно от нашей СЧА. При выплате вводится фактическая сумма; разница проводится корректирующим начислением в дату выплаты, обязательство обнуляется. Корректировка видна в журнале и в разложении P&L. |
| 44 | Количество паёв считается в системе по операциям выдачи и погашения. |
| 45 | Бумаги переводятся по средней цене портфеля-отправителя, без финансового результата; одна дата исполнения для обеих сторон. |
| 46 | Парсеры отчётов брокеров — позже. Сейчас нужен только приёмник остатков. |
| 47 | Тип денежного счёта: брокерский или банковский. Остаток банковского счёта сопровождение вводит вручную по выписке. |
| 48 | День закрывается по фонду целиком, после сверки всех счетов фонда. |
| 49 | MVP: облигации с фиксированным купоном, флоатеры, РЕПО, БПИФ. Фьючерсы и OIS — второй этап. |

## Справочник инструментов и расчёты (2026-10-26)

| № | Решение |
|---|---|
| 10 | Поддерживаем амортизацию и колл-опционы эмитента. ОФЗ-ИН (индексация на ИПЦ) не поддерживаем. |
| 11 | Купоны, оферты и амортизации берём из MOEX ISS. Сопровождение может поправить параметры вручную; каждая правка — новая версия инструмента. |
| 13 | Новая версия инструмента действует с даты публикации новых купонов. Расчёты за прошлые дни остаются на старой версии. |
| 25 (справочник) | Загрузить новую бумагу могут и трейдинг, и сопровождение: в интерфейсе вводят код бумаги, система находит её в MOEX ISS и загружает. Править бумагу может только сопровождение — и ежедневная автоматическая синхронизация с MOEX ISS. Роли в сделках и операциях — открытый вопрос 25. |
| 56 | Весь список облигаций биржи не загружаем — только бумаги, которые добавили пользователи. |
| 57 | Торговый календарь ведём в системе; переносы выходных сопровождение заносит раз в год. |
| 58 | Дата расчётов всегда есть в данных сделки. Срок по умолчанию (T+1 для облигаций и паёв, T+0 для размещений и РЕПО) — только подсказка при ручном вводе. |
| 16 | НКД не рассчитываем сами — берём из MOEX ISS. Это позволяет считать стоимость (MV) и результат (P&L) позиций и в реальном времени, и за прошлую дату. Эталонный Excel для НКД не нужен. |
| 15 | Для вменённого кредитного спреда флоатера купон полностью не моделируем. Достаточно: маржи к плавающей ставке, текущих чистой и грязной цен, типа плавающей ставки (сама ставка и признак капитализации), расписания купонов, признака индексации номинала. |
| 59 | Поле, поправленное сопровождением вручную, закрепляется: синхронизация с ISS его не перезаписывает, но показывает расхождение. |
| 60 | ISS публикует НКД на дату расчётов. Для нерасчётных дней НКД интерполируем сами. |
| 61 | Подписки на данные ISS нет — пользуемся только открытой частью. |
| 63 | Версия бумаги хранит только условия выпуска. Номинал на дату в версию не входит: у обычной облигации он следует из начального номинала и графика амортизаций, у облигации с индексируемым номиналом — из ряда «бумага, дата, номинал». Ряд загружаем из истории торгов ISS на шаге 3, вместе с НКД. Суммы будущих купонов и погашения линкера ISS пересчитывает каждый день по текущему номиналу — это прогноз, поэтому справочник хранит сумму платежа только с дня выплаты. Иначе линкер получал бы новую версию каждый торговый день, а первая версия переносила бы сегодняшний номинал на все прошлые даты. |

## Рыночные данные (2026-10-27)

| № | Решение |
|---|---|
| 64 | Цены присылает собственный скрипт пользователя: JSON по нашей спецификации ([api/price-feed](api/price-feed/README.md)) — снимки цен и OHLC-бары. Скрипт входит служебным клиентом Keycloak по client credentials. |
| 65 | Цена для оценки по умолчанию — VWAP; правило задаётся на каждую бумагу. Отдельный интерфейс показывает все цены бумаги и разброс между ними. |
| 66 | OHLC-бары — по желанию на бумагу, таймфрейм любой (10 минут, 30 минут, час…). Если бары есть, система считает DEMA по ценам закрытия, чтобы сгладить цену неликвидной бумаги. Период полураспада задаётся в минутах на бумагу. |
| 67 | Ручную цену вводит трейдинг, без подтверждения. |
| 68 | Переоценка внутри дня — в MVP. |
| 69 | DEMA: вес бара зависит только от его длины. Ночь, выходные и интервалы без сделок среднюю не «старят». |
| 70 | Ручная цена действует до конца торгового дня — и только: своего срока и отдельной отмены нет, ошибочную цену исправляют новой ручной ценой. Правило оценки и параметры DEMA меняет трейдинг; изменение действует с момента сохранения. |
| 71 | Нет цены за сегодня — берём следующий тип правила; если ни у одного типа нет значения за сегодня — последнее известное значение первого типа с пометкой «устарела». |
| 72 | ISS внутри дня (открытая часть, задержка 15 минут) — дополнительный источник: опрашиваем раз в 5 минут. |
| 73 | НКД на дату без точки ISS: от ближайшей предыдущей точки прибавляем дневное начисление (сумма купона / дней в периоде); если сумма купона неизвестна — линейно между точками ISS; округляем до копейки один раз. |
| 74 | Одна цена для длинных и коротких позиций; bid и ask можно выбрать в правило бумаги. |

## Расчёты по облигациям (2026-10-29)

| № | Решение |
|---|---|
| 12 | Доходности и спреды — эффективные годовые: база дней ACT/365, годовая капитализация. Для спредов флоатеров и линкеров тоже (подтверждено 2026-10-29): вариант «надбавка к ставке RUONIA», где спред ближе к марже из проспекта, рассмотрен и отклонён. |
| 16 (эталоны) | Методику расчётов пишем мы, пользователь подтверждает её правильность. С биржей сверяемся, пока разрабатываем и проверяем методику; после этого доверяем собственным эталонам — тесты сверяют расчёт с нашими числами, а не с ISS. Бумаги для эталонов: ОФЗ 26238, бумага с офертой и бумага с амортизацией. |
| 23 | Метрики облигаций: модифицированная дюрация, DV01, выпуклость. KRD не нужен. |
| 75 | Для флоатеров и линкеров уже на шаге 4 считаем не доходность, а вменённый кредитный спред над кривой фондирования. Фондирование моделируем по RUONIA. Спред = статика (маржа флоатера) с поправками на рыночную цену бумаги (дисконт или премия), на базис плавающей ставки к RUONIA (например, для флоатера на ключевую ставку) и на капитализацию ставки (если её нет — поправка с учётом частоты купонов). Тип плавающей ставки, признак капитализации и индексацию номинала ведёт вручную сопровождение в справочнике. |
| 76 | Ставки для спредов. RUONIA присылает скрипт — метод `/feed/v1/rates` спецификации docs/api/price-feed. Ключевую ставку и RUSFAR сервис рыночных данных берёт из индексов ISS KEYRATE и RUSFAR; ставка скрипта на ту же дату главнее. Действует последняя известная ставка не позже дня цены. |
| 77 | Базис ставки индекса к RUONIA — из текущих уровней ставок: при плоском прогнозе это последовательно. |
| 78 | Горизонт облигации с офертой: главная доходность — к ближайшей оферте, которую ещё можно предъявить; к погашению — только если объявлены все купоны до погашения. Спред флоатера и линкера — к тому же горизонту. |
| 79 | Эталоны флоатеров — настоящие бумаги: Газпром нефть 003P-08R (КС + 1,30), 003P-09R (RUONIA + 1,40), РЖД 001P-48R (RUONIA + 1,75, оферта). |
| 80 | Доходности и спреды считаем от даты расчётов T+1 по торговому календарю, как биржа. |
