# Как присылать сделки: спецификация v1

Документ для автора скрипта или внешней системы, которая присылает сделки
фондов. Здесь всё, что нужно, чтобы импорт заработал с первого раза: вход,
формат пакета, как система понимает повтор и исправление, ответ, ошибки,
примеры.

> **Коротко**
>
> - Скрипт получает токен в Keycloak по client credentials и отправляет JSON в `POST /api/booking/feed/v1/trades`. Тот же файл можно загрузить в интерфейсе: «Сделки» → «Импорт».
> - Ключ сделки — источник (`source`) и номер сделки в источнике (`external_id`). Новый номер — новая сделка, тот же номер с другими полями — новая версия сделки, с теми же полями — ничего не меняется.
> - Повторная отправка безопасна: дублей не будет.
> - Отменённую в источнике сделку присылают целиком с `"cancelled": true`.
> - Сумму сделки считает система. НКД и номинал можно не присылать — система возьмёт их из рыночных данных.
> - Плохая сделка отклоняется отдельно, остальные сделки пакета принимаются. Ответ говорит, какие сделки отклонены и почему.
> - Сделки РЕПО с НКЦ идут в том же пакете: `"kind": "repo"`, ставка, дата и сумма второй части по отчёту брокера. Обеспечение КСУ — код `KSU`.

Файлы рядом:

| Файл | Что это |
|---|---|
| [trades.schema.json](trades.schema.json) | JSON Schema пакета сделок |
| [trades.example.json](trades.example.json) | пример пакета: покупка и продажа ОФЗ из методики, покупка паёв фонда ликвидности |
| [repo.example.json](repo.example.json) | пример пакета РЕПО: размещение в РЕПО с КСУ и привлечение под ОФЗ из методики шага 7 |

Пример из этой папки система проверяет в своих тестах: если формат
изменится, тесты упадут, и спецификацию обновят вместе с кодом.

## Вход

Скрипт — служебный клиент Keycloak `am-trade-feed` с ролью `trade_feed`.
Пароль клиента (client secret) выдаёт администратор. В окружении
разработки — `trade-feed-dev`. Скрипт видит все портфели: внешняя система
присылает сделки всех фондов (вопрос 100).

Получить токен:

```bash
curl -s -X POST http://localhost:8080/auth/realms/am/protocol/openid-connect/token \
  -d grant_type=client_credentials \
  -d client_id=am-trade-feed \
  -d client_secret=trade-feed-dev
```

В ответе — `access_token` и `expires_in` (секунды, обычно 300). Токен
передаётся в заголовке каждого запроса:

```
Authorization: Bearer <access_token>
```

Пользователь — трейдинг, сопровождение, администратор — загружает файл
в интерфейсе. Сделки он может загрузить только в портфели, к которым
у него есть доступ.

## Пакет сделок

`POST /api/booking/feed/v1/trades`

В пакете — до 5000 сделок одного источника.

```json
{
  "source": "broker-x",
  "trades": [
    {
      "external_id": "BX-2026-11-27-0042",
      "portfolio": "OPIF1-BONDS",
      "code": "SU26238RMFS4",
      "side": "buy",
      "quantity": 50000,
      "price": 52.5,
      "trade_at": "2026-11-27T11:42:00+03:00",
      "settle_date": "2026-11-30",
      "accrued": 35.01
    }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `source` | да | Откуда сделки: короткий код вроде `broker-x` или `oms`. Латиница в нижнем регистре, цифры, `-`, `_`, до 32 символов |
| `external_id` | да | Номер сделки в источнике, до 64 символов. Не меняется, пока сделка живёт |
| `portfolio` | да | Код портфеля в системе — physical-портфель со счётом, например `OPIF1-BONDS` |
| `code` | да | Код бумаги на бирже (SECID) или ISIN. Бумага должна быть в справочнике |
| `side` | да | `buy` — покупка, `sell` — продажа |
| `quantity` | да | Количество бумаг, штук |
| `price` | да | Облигация — чистая цена в процентах от номинала: `52.5`, а не `525` рублей. Пай — цена в рублях за пай. До 6 знаков после запятой |
| `trade_at` | да | Время заключения сделки со смещением часового пояса |
| `settle_date` | да | Дата расчётов. Торговый день, не раньше даты сделки |
| `accrued` | нет | Облигация: НКД на одну бумагу на дату расчётов, рубли. Нет — система возьмёт из рыночных данных |
| `face_value` | нет | Облигация: номинал одной бумаги на дату расчётов, рубли. Нет — из рыночных данных или по графику погашений |
| `fee` | нет | Комиссия брокера и биржи, рубли, до 2 знаков. Нет — 0 |
| `venue` | нет | `exchange` — биржа (по умолчанию), `otc` — внебиржевая сделка |
| `counterparty` | нет | Контрагент внебиржевой сделки |
| `comment` | нет | Комментарий: попадёт в версию сделки и в журнал |
| `cancelled` | нет | `true` — сделка отменена в источнике |
| `kind` | нет | `outright` — покупка или продажа (по умолчанию), `repo` — сделка РЕПО с НКЦ |
| `amount` | РЕПО с КСУ | Сумма первой части, рубли. У остальных сделок сумму считает система |
| `repo_rate` | РЕПО | Ставка РЕПО, % годовых: `14.5` |
| `second_date` | РЕПО | Дата второй части — торговый день позже первой |
| `second_amount` | РЕПО | Сумма второй части по отчёту брокера, рубли |

**Сумма сделки.** Её считает система: количество × (цена × номинал / 100 +
НКД на бумагу), до копейки. У пая — количество × цена.

**НКД и номинал.** Если источник знает НКД из подтверждения брокера,
присылайте его: так сумма совпадёт с брокерской до копейки. Если не
присылать, система возьмёт НКД на дату расчётов из рыночных данных. Не
нашлось — сделка будет отклонена с кодом `accrued_required`.

## РЕПО

Сделки РЕПО — только биржевые, с НКЦ. В пакете это та же сделка
с `"kind": "repo"` и тремя полями второй части:

```json
{
  "external_id": "BX-2026-11-30-R002",
  "portfolio": "OPIF1-BONDS",
  "code": "SU26238RMFS4",
  "kind": "repo",
  "side": "sell",
  "quantity": 10000,
  "price": 52.6,
  "accrued": 35.01,
  "trade_at": "2026-11-30T11:05:00+03:00",
  "settle_date": "2026-11-30",
  "repo_rate": 14.5,
  "second_date": "2026-12-03",
  "second_amount": 5616786.01
}
```

- `side` — сторона первой части: `sell` — прямое РЕПО, фонд отдаёт бумаги
  и получает деньги; `buy` — обратное, фонд размещает деньги.
- `settle_date`, `price`, `accrued` — первой части. Сумму первой части
  считает система, как у покупки и продажи.
- `second_amount` — из отчёта брокера. Система сверяет её со ставкой
  и сроком и предупреждает, если она отличается больше чем на рубль.
- Обеспечение КСУ: `"code": "KSU"`, без `quantity` и `price`, с суммой
  первой части в `amount`.
- Досрочное исполнение — тот же `external_id` с новыми `second_date`
  и `second_amount`: сделка получит новую версию.

Компенсационные взносы по РЕПО импорт не принимает: их вводит сопровождение
по отчёту брокера.

## Повтор и исправление

Ключ сделки — `source` и `external_id`. Пришла сделка с ключом:

| Что в системе | Что пришло | Что делает система | `result` в ответе |
|---|---|---|---|
| сделки с таким ключом нет | сделка | вводит новую сделку | `created` |
| сделка есть | те же поля | ничего | `unchanged` |
| сделка есть | другие поля | новая версия сделки, старая остаётся в истории | `amended` |
| сделка есть | `"cancelled": true` | версия «отменена» | `cancelled` |
| сделка уже отменена | `"cancelled": true` | ничего | `unchanged` |

Поэтому скрипт может:

- повторить пакет после ошибки сети или ответа 503 — дублей не будет;
- присылать за день все сделки целиком, а не только новые;
- исправить сделку: тот же `external_id` с новыми полями.

Сравниваются поля сделки после подстановки: портфель, бумага, направление,
количество, цена, номинал, НКД, сумма, комиссия, время, дата расчётов, место,
контрагент, а у РЕПО — ставка, дата и сумма второй части. Комментарий
не сравнивается.

**Подтверждённая сделка.** Сопровождение сверяет сделку с подтверждением
брокера и подтверждает её. Подтверждённую сделку скрипт не меняет и не
отменяет: она будет отклонена с кодом `confirmed_trade`. Исправить её может
сопровождение — в интерфейсе или загрузив файл.

**Отменённая сделка** не возвращается: сделка с тем же ключом без
`cancelled` будет отклонена с кодом `trade_cancelled`. Если сделку отменили
по ошибке, пришлите её под новым `external_id`.

## Ответ

Сервис обработал пакет — ответ 200:

```json
{
  "created": 1,
  "amended": 0,
  "cancelled": 0,
  "unchanged": 1,
  "trades": [
    {
      "index": 0,
      "external_id": "BX-2026-11-27-0042",
      "result": "unchanged",
      "trade_id": "5b0b8f0e-1f7c-4c55-9a3e-1d7c2f4f8e21",
      "warnings": []
    },
    {
      "index": 1,
      "external_id": "BX-2026-11-30-0017",
      "result": "created",
      "trade_id": "8c2e4a51-0d6b-4f0e-b5a7-6a0d9f1c3e42",
      "warnings": [
        "Продажа больше позиции: на 30.11.2026 в портфеле 0 шт., продаётся 20000. Дефицит к расчётам покажет лестница."
      ]
    }
  ],
  "rejected": [
    {
      "index": 2,
      "external_id": "BX-2026-11-27-0051",
      "error": "unknown_instrument",
      "message": "Бумаги LQDT нет в справочнике. Загрузите её в разделе «Справочник»."
    }
  ]
}
```

- `created`, `amended`, `cancelled`, `unchanged` — сколько сделок как
  обработано.
- `trades` — принятые сделки: номер в пакете (`index`, с нуля), номер в
  источнике, что сделано, id сделки в системе и предупреждения.
- `rejected` — отклонённые сделки: номер в пакете, номер в источнике, код
  ошибки и сообщение для человека. Пустой список — принято всё.

**Предупреждение** не мешает принять сделку. Например, продажа больше
позиции: так бывает, когда покупка ещё не пришла. Дефицит к расчётам
покажет лестница.

Скрипту стоит записывать отклонённые сделки в свой лог: сами они не
появятся. Каждая принятая сделка видна в журнале действий: кто, когда
и что изменил.

| Код ошибки | Что не так | Что делать |
|---|---|---|
| `portfolio_unavailable` | портфеля с таким кодом нет или к нему нет доступа | проверить код портфеля; пользователю — запросить доступ |
| `portfolio_not_physical` | портфель составной — в нём нет счёта | указать physical-портфель |
| `unknown_instrument` | бумаги нет в справочнике | загрузить бумагу в справочник, повторить |
| `not_issued` | на дату расчётов бумага ещё не выпущена | проверить бумагу и дату |
| `matured` | бумага погашена до даты расчётов | проверить бумагу и дату |
| `future_trade` | дата сделки позже сегодняшней | проверить `trade_at` и часовой пояс |
| `settle_before_trade` | дата расчётов раньше даты сделки | проверить `settle_date` |
| `settle_not_trading_day` | дата расчётов — не торговый день | проверить `settle_date` |
| `face_value_required` | номинал на дату расчётов неизвестен: так бывает у линкеров | прислать `face_value` |
| `accrued_required` | НКД на дату расчётов неизвестен | прислать `accrued` |
| `confirmed_trade` | сделку уже подтвердило сопровождение | исправляет сопровождение |
| `trade_cancelled` | сделка с этим ключом отменена | прислать под новым `external_id` |
| `unknown_trade` | отменяют сделку, которой нет | проверить `external_id` |
| `duplicate_in_batch` | `external_id` дважды в одном пакете | оставить одну запись |
| `concurrent_import` | ту же новую сделку в ту же секунду загрузил другой пакет | повторить пакет |
| `quantity_required` | у сделки с бумагой нет количества или цены | прислать `quantity` и `price` |
| `instrument_required` | код `KSU` у сделки, которая не РЕПО | указать бумагу или `"kind": "repo"` |
| `repo_terms_required` | у РЕПО нет ставки, даты или суммы второй части | прислать `repo_rate`, `second_date`, `second_amount` |
| `repo_amount_required` | у РЕПО с КСУ нет суммы первой части | прислать `amount` |
| `repo_not_exchange` | РЕПО с `"venue": "otc"` | РЕПО — только биржевые сделки с НКЦ |
| `repo_collateral` | обеспечение РЕПО — не облигация | РЕПО — с облигациями или с КСУ |
| `second_before_first` | вторая часть не позже первой | проверить `second_date` |
| `second_not_trading_day` | дата второй части — не торговый день | проверить `second_date` |

Другие ответы:

| Код | Когда | Что делать |
|---|---|---|
| 401 | нет токена или он истёк | получить новый токен, повторить |
| 403 | у клиента нет роли `trade_feed` | обратиться к администратору |
| 422 | пакет не проходит JSON Schema — не принято ничего | исправить формат; в ответе список ошибок |
| 503 | справочник, рыночные данные или сервис портфелей временно недоступны | повторить пакет целиком через минуту: повтор безопасен |

При ответе 503 часть сделок пакета может быть уже принята. Повторите
пакет целиком: принятые сделки вернутся как `unchanged`.

## Проверить пакет до отправки

```bash
uvx check-jsonschema --schemafile docs/api/trade-import/trades.schema.json my-batch.json
```

Схема проверяет форму пакета. Есть ли портфель и бумага, торговый ли день
расчётов, проверит только сервис — без записи, с параметром `dry_run`:

```bash
curl -s -X POST "https://<адрес>/api/booking/feed/v1/trades?dry_run=true" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  --data-binary @my-batch.json
```

Ответ — тот же, что при загрузке: что станет с каждой сделкой и что
отклонено. У новых сделок `trade_id` — `null`: их ещё нет.

## Пример на Python

```python
import requests

BASE = "http://localhost:8080"
CLIENT = {"client_id": "am-trade-feed", "client_secret": "trade-feed-dev"}


def token() -> str:
    response = requests.post(
        f"{BASE}/auth/realms/am/protocol/openid-connect/token",
        data={"grant_type": "client_credentials", **CLIENT},
        timeout=10,
    )
    response.raise_for_status()
    return response.json()["access_token"]


def send_trades(trades: list[dict]) -> None:
    response = requests.post(
        f"{BASE}/api/booking/feed/v1/trades",
        json={"source": "broker-x", "trades": trades},
        headers={"Authorization": f"Bearer {token()}"},
        timeout=120,
    )
    response.raise_for_status()
    report = response.json()
    print({key: report[key] for key in ("created", "amended", "cancelled", "unchanged")})
    for item in report["rejected"]:
        print(f"отклонено: {item['external_id']} — {item['message']}")


send_trades(
    [
        {
            "external_id": "BX-2026-11-27-0042",
            "portfolio": "OPIF1-BONDS",
            "code": "SU26238RMFS4",
            "side": "buy",
            "quantity": 50000,
            "price": 52.5,
            "trade_at": "2026-11-27T11:42:00+03:00",
            "settle_date": "2026-11-30",
        }
    ]
)
```

Каждая сделка — отдельная транзакция с проверками, версией и записью
в журнал. На тестовом стенде пакет из 1000 новых сделок обработался
за 14 секунд, повтор того же пакета — за 6 секунд. С такой скоростью
пакет из 5000 новых сделок займёт больше минуты: ставьте таймаут запроса
не меньше 120 секунд или присылайте пакеты по 1000 сделок.

## Версии

Это версия 1 — она в адресе: `/feed/v1/`. Новые необязательные поля могут
появиться без смены версии; сервис их опишет здесь. Всё, что сломает
работающий скрипт, выйдет как `/feed/v2/`, а v1 продолжит работать, пока
скрипт не перейдёт.
