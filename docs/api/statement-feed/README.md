# Как присылать выписки по счетам: спецификация v1

Документ для автора скрипта, который переводит отчёты брокера в формат
системы. Здесь всё, чтобы приём заработал с первого раза: вход, формат пакета,
проверки, повтор и исправление, ответ, ошибки, пример.

> **Коротко**
>
> - Скрипт получает токен в Keycloak по client credentials и отправляет JSON в `POST /api/reconciliation/feed/v1/statements`.
> - Выписка — всё, что произошло на счёте за день: остаток денег на начало и на конец, сделки дня, движения денег.
> - Остаток на начало плюс движения должны дать остаток на конец. Не дают — выписка отклоняется: в ней не хватает движения.
> - Та же выписка ещё раз ничего не меняет. Другая выписка за тот же счёт и день становится действующей, прежняя остаётся в истории.
> - Плохая выписка отклоняется отдельно, остальные выписки пакета принимаются. Пакет хранится целиком, как пришёл.
> - Остатки бумаг не присылают: их пока не сверяем (решение 118).

Файлы рядом:

| Файл | Что это |
|---|---|
| [statements.schema.json](statements.schema.json) | JSON Schema пакета выписок |
| [statements.example.json](statements.example.json) | пример: неделя брокерского счёта «ОПИФ 1» из методики шага 8 |

Пример из этой папки система проверяет в своих тестах: если формат
изменится, тесты упадут, и спецификацию обновят вместе с кодом.

## Вход

Скрипт — служебный клиент Keycloak `am-statement-feed` с ролью
`statement_feed`. Пароль клиента (client secret) выдаёт администратор.
В окружении разработки — `statement-feed-dev`. Скрипт видит все счета:
брокер присылает выписки всех фондов.

Получить токен:

```bash
curl -s -X POST http://localhost:8080/auth/realms/am/protocol/openid-connect/token \
  -d grant_type=client_credentials \
  -d client_id=am-statement-feed \
  -d client_secret=statement-feed-dev
```

В ответе — `access_token` и `expires_in` (секунды, обычно 300). Токен
передаётся в заголовке каждого запроса:

```
Authorization: Bearer <access_token>
```

Выписку банка и выписку брокера без скрипта сопровождение вводит вручную:
«Сверка» → «Выписки». Пакет от пользователя этот адрес не принимает.

## Пакет выписок

`POST /api/reconciliation/feed/v1/statements`

В пакете — до 1000 выписок одного источника.

```json
{
  "source": "broker-x",
  "statements": [
    {
      "account": "OPIF1-BROKER",
      "date": "2026-11-30",
      "opening_cash": 60000000.00,
      "closing_cash": 31996699.95,
      "trades": [
        {
          "external_id": "1000000002",
          "side": "sell",
          "security": "SU26238RMFS4",
          "settle_date": "2026-12-01",
          "quantity": 25000,
          "price": 52.60,
          "accrued": 35.21,
          "amount": 14030250.00,
          "fee": 0
        }
      ],
      "movements": [
        { "kind": "settlement", "trade": "1000000001", "amount": -28000500.00 },
        { "kind": "fee", "trade": "1000000001", "amount": -2800.05 }
      ]
    }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `source` | да | кто прислал: код брокера или скрипта |
| `account` | да | код счёта в системе, например `OPIF1-BROKER` |
| `date` | да | день выписки; не позже сегодняшнего |
| `opening_cash`, `closing_cash` | да | деньги на счёте на начало и на конец дня, ₽ до копейки |
| `trades` | нет | сделки, заключённые в этот день |
| `movements` | нет | деньги, которые в этот день пришли (+) или ушли (−) |

Числа — числом или строкой: `52.6` и `"52.60"` — одно и то же.

## Сделки дня

Поля — как в [импорте сделок](../trade-import/README.md), кроме портфеля
и времени: выписка относится к счёту, а время заключения система не сверяет.

| Поле | Обязательно | Что это |
|---|---|---|
| `external_id` | да | номер сделки биржи — по нему сделка выписки находит свою пару в системе |
| `kind` | нет | `outright` — покупка или продажа (по умолчанию), `repo` — РЕПО с НКЦ |
| `side` | да | `buy` или `sell`; у РЕПО — сторона первой части, `sell` — прямое |
| `security` | да | SECID или ISIN; `KSU` — РЕПО с КСУ |
| `settle_date` | да | дата расчётов; у РЕПО — первой части |
| `quantity`, `price` | у сделки с бумагой | количество и цена: облигация — % от номинала, пай — ₽ за пай; у РЕПО с КСУ — 0 |
| `accrued` | у облигации | НКД на одну бумагу, ₽ |
| `amount` | да | сумма сделки; у РЕПО — первой части |
| `fee` | нет | комиссия брокера и биржи по сделке, ₽ |
| `repo_rate`, `second_date`, `second_amount` | у РЕПО | ставка, % годовых, дата и сумма второй части |

## Движения денег

У каждого движения — вид, сумма со знаком и ключ, по которому система
находит пару:

| Вид | Что | Ключ |
|---|---|---|
| `settlement` | расчёты по покупке или продаже | `trade` — номер сделки |
| `fee` | комиссия по сделке | `trade` |
| `repo_first`, `repo_second` | первая и вторая часть РЕПО | `trade` |
| `repo_contribution` | компенсационный взнос | `trade` |
| `coupon`, `amortization`, `redemption` | выплата по бумаге | `security`; передача дохода по РЕПО — ещё и `trade` |
| `transfer` | перевод между счетами фонда | — |
| `unit_settlement` | расчёт по паям | — |
| `fee_payment` | вознаграждение и комиссии от СЧА | — |
| `expense_payment` | выплата расхода фонда | — |
| `other` | всё остальное | — |

Движения без ключа система сравнивает суммой за день по виду: банк может
показать расчёт по паям десятью платежами пайщиков, система — одной
операцией. У движения может быть `comment` — например, плательщик.

## Что проверяет система

| Проверка | Что будет |
|---|---|
| Пакет по схеме: поля, виды, ключи движений | не так — весь пакет отклоняется, ответ 422 |
| Остаток на начало плюс движения — остаток на конец | не так — выписка отклоняется: `statement_does_not_add_up` |
| Счёт есть в системе | нет — `unknown_account` |
| Бумага есть в справочнике | нет — `unknown_security` |
| День — не позже сегодняшнего | позже — `future_statement` |
| Одна выписка на счёт и день в пакете | две — обе отклоняются: `repeated_statement` |
| Один номер сделки в выписке | два — `repeated_trade` |
| `KSU` — только в РЕПО | нет — `ksu_not_repo` |

Пример отказа: скрипт потерял строку комиссии.

```
OPIF1-BROKER, 30.11.2026: остаток на начало 60 000 000,00 ₽ и движения
−28 000 500,00 ₽ дают 31 999 500,00 ₽, а остаток на конец — 31 996 699,95 ₽.
Не хватает движений на −2 800,05 ₽.
```

## Повтор и исправление

- **Та же выписка ещё раз** — ничего не меняется: `unchanged`. Повтор пакета
  безопасен.
- **Брокер исправил отчёт** — пришлите выписку за тот же счёт и день заново:
  `replaced`. Действует последняя, прежняя остаётся в истории.
- **Выписка за закрытый день** принимается, но день не открывает: сверка
  покажет расхождение, а открывает день администратор (решение 128).

## Ответ

```json
{
  "batch_id": "5f0c…",
  "created": 1,
  "replaced": 0,
  "unchanged": 0,
  "statements": [
    { "index": 0, "account": "OPIF1-BROKER", "date": "2026-11-30", "statement_id": "9a1e…", "result": "created" }
  ],
  "rejected": [
    {
      "index": 1,
      "account": "OPIF9-BROKER",
      "date": "2026-11-30",
      "error": "unknown_account",
      "message": "Счёта OPIF9-BROKER нет в системе или к нему нет доступа."
    }
  ]
}
```

`index` — номер выписки в пакете, с нуля.

| Код ответа | Что значит |
|---|---|
| 200 | пакет разобран: что принято и что отклонено — в ответе |
| 401 | нет токена или он просрочен |
| 403 | у учётной записи нет роли `statement_feed` |
| 422 | пакет не по схеме |
| 503 | сервис портфелей или справочник недоступен — повторите позже |

## Пример

Неделя брокерского счёта «ОПИФ 1» из методики шага 8 —
[statements.example.json](statements.example.json):

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/auth/realms/am/protocol/openid-connect/token \
  -d grant_type=client_credentials -d client_id=am-statement-feed \
  -d client_secret=statement-feed-dev | jq -r .access_token)

curl -s -X POST http://localhost:8080/api/reconciliation/feed/v1/statements \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  --data @docs/api/statement-feed/statements.example.json
```
