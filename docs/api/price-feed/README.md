# Как скрипту присылать цены: спецификация v1

Документ для автора скрипта, который присылает в систему цены и ставки.
Здесь всё, что нужно, чтобы скрипт заработал с первого раза: вход, формат
пакетов, ответы, ошибки, примеры.

> **Коротко**
>
> - Скрипт получает токен в Keycloak по client credentials и отправляет JSON в три адреса: снимки цен — `POST /api/marketdata/feed/v1/quotes`, OHLC-бары — `POST /api/marketdata/feed/v1/bars`, ставки — `POST /api/marketdata/feed/v1/rates`.
> - RUONIA присылает только скрипт: без неё система не посчитает спреды флоатеров и линкеров.
> - Облигации — чистая цена в процентах от номинала. Паи — цена в валюте за пай.
> - Время — со смещением часового пояса: `2026-10-27T11:05:00+03:00`.
> - Повторная отправка безопасна: действует последнее полученное значение.
> - Плохая цена отклоняется отдельно, остальные цены пакета принимаются. Ответ говорит, какие цены отклонены и почему.

Файлы рядом:

| Файл | Что это |
|---|---|
| [quotes.schema.json](quotes.schema.json) | JSON Schema пакета снимков цен |
| [quotes.example.json](quotes.example.json) | пример пакета снимков цен |
| [bars.schema.json](bars.schema.json) | JSON Schema пакета баров |
| [bars.example.json](bars.example.json) | пример пакета баров |
| [rates.schema.json](rates.schema.json) | JSON Schema пакета ставок |
| [rates.example.json](rates.example.json) | пример пакета ставок |

Примеры из этой папки система проверяет в своих тестах: если формат
изменится, тесты упадут, и спецификацию обновят вместе с кодом.

## Вход

Скрипт — служебный клиент Keycloak `am-price-feed` с ролью `price_feed`.
Пароль клиента (client secret) выдаёт администратор. В окружении
разработки — `price-feed-dev`.

Получить токен:

```bash
curl -s -X POST http://localhost:8080/auth/realms/am/protocol/openid-connect/token \
  -d grant_type=client_credentials \
  -d client_id=am-price-feed \
  -d client_secret=price-feed-dev
```

В ответе — `access_token` и `expires_in` (секунды, обычно 300). Токен
передаётся в заголовке каждого запроса:

```
Authorization: Bearer <access_token>
```

Истёк токен — сервис ответит 401. Получите новый и повторите запрос.

## Снимки цен

`POST /api/marketdata/feed/v1/quotes`

Снимок — цены одной бумаги на один момент. В пакете — до 5000 снимков.

```json
{
  "source": "quik",
  "quotes": [
    {
      "code": "SU26238RMFS4",
      "time": "2026-10-27T11:05:00+03:00",
      "vwap": 51.823,
      "last": 51.789,
      "bid": 51.784,
      "ask": 51.789
    }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `source` | да | Откуда цены: короткий код вроде `quik` или `broker-x`. Латиница в нижнем регистре, цифры, `-`, `_`, до 32 символов. В интерфейсе цены разных источников видны отдельно |
| `code` | да | Код бумаги на бирже (SECID) или ISIN. Бумага должна быть в справочнике |
| `time` | да | Момент, к которому относятся цены. Не время отправки |
| `vwap` | нет | Средневзвешенная по объёму цена сделок с начала торгового дня до `time` |
| `last` | нет | Цена последней сделки до `time` |
| `bid` | нет | Лучшая цена покупки на `time` |
| `ask` | нет | Лучшая цена продажи на `time` |
| `close` | нет | Цена закрытия торгового дня. `time` — конец торгового дня |
| `market_price` | нет | Рыночная цена биржи |
| `admitted_quote` | нет | Признаваемая котировка биржи |

В снимке должна быть хотя бы одна цена. Присылайте только те цены, что
есть у источника: пустых значений и нулей не нужно.

**Единицы.** Облигация — чистая цена в процентах от номинала: `99.71`,
а не `997.10` рубля. Пай фонда — цена в валюте за пай. До 6 знаков после
запятой.

**Как часто.** Снимок по бумаге — раз в 1–5 минут, пока идут торги. Чаще
раза в минуту не нужно.

## OHLC-бары

`POST /api/marketdata/feed/v1/bars`

Бар — цены открытия, максимума, минимума и закрытия бумаги за интервал.
Бары присылаются по желанию, только для бумаг, где нужна сглаженная цена.
По ценам закрытия система считает DEMA.

```json
{
  "source": "quik",
  "bars": [
    {
      "code": "RU000A10F504",
      "timeframe": "10m",
      "start": "2026-10-27T10:00:00+03:00",
      "open": 99.69,
      "high": 99.72,
      "low": 99.68,
      "close": 99.70,
      "volume": 1520
    }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `source` | да | Как в снимках цен |
| `code` | да | Как в снимках цен |
| `timeframe` | да | Длина бара: от `1m` до `240m` или от `1h` до `4h`. Например, `10m`, `30m`, `1h` |
| `start` | да | Начало бара. По московскому времени кратно длине бара от полуночи: для `10m` — 10:00, 10:10, 10:20; для `1h` — 10:00, 11:00 |
| `open`, `high`, `low`, `close` | да | Цены в тех же единицах, что и снимки |
| `volume` | нет | Объём в штуках бумаг |

**Когда присылать.** Бар — после того как интервал закончился. Интервал
без сделок не присылайте: пустых баров не бывает. По одной бумаге можно
присылать бары нескольких таймфреймов, каждый ряд хранится отдельно.

**Что проверяет сервис**, кроме схемы:

- `high` не меньше `open`, `close` и `low`; `low` не больше `open` и `close`;
- `start` выровнен по длине бара.

## Ставки

`POST /api/marketdata/feed/v1/rates`

Ставки нужны для спредов флоатеров и линкеров: фондирование система считает
по RUONIA, флоатер на ключевую ставку сравнивает с ней через базис. RUONIA
биржа не публикует — её присылает скрипт, раз в день, после публикации
Банком России. Ключевую ставку и RUSFAR система каждое утро берёт из ISS
сама; скрипт может прислать и их — тогда на ту же дату действует ставка
скрипта.

```json
{
  "source": "cbr",
  "rates": [
    { "rate": "ruonia", "date": "2026-10-26", "value": 13.90 }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `source` | да | Откуда ставки: например, `cbr`. Правила — как в снимках цен |
| `rate` | да | `ruonia` — RUONIA, `key_rate` — ключевая ставка, `rusfar` — RUSFAR overnight |
| `date` | да | Дата, за которую ставка, а не дата публикации: RUONIA за 26.10 публикуется 27.10, `date` — `2026-10-26` |
| `value` | да | Ставка в % годовых: `13.90`, а не `0.139`. До 4 знаков после запятой |

**Какая ставка действует.** На дату расчёта — последняя известная ставка не
позже этой даты. Скрипт не прислал RUONIA за вчера — система возьмёт
позавчерашнюю и покажет её дату рядом со спредом.

**Что проверяет сервис**, кроме схемы: дата ставки — не позже сегодняшней
по Москве.

## Ответ

Сервис обработал пакет — ответ 200:

```json
{
  "batch_id": "3f1d2b6a-6c0e-4c55-9a3e-1d7c2f4f8e21",
  "accepted": 2,
  "rejected": [
    {
      "index": 1,
      "code": "XS0000000000",
      "error": "unknown_instrument",
      "message": "Бумаги XS0000000000 нет в справочнике. Загрузите её в разделе «Справочник»."
    }
  ]
}
```

- `accepted` — сколько снимков, баров или ставок принято.
- `rejected` — что отклонено: номер в пакете (`index`, с нуля), код бумаги
  (у ставки — её код, например `ruonia`), код ошибки и сообщение для
  человека. Пустой список — принято всё.

Скрипту стоит записывать отклонённые цены в свой лог: сами они не появятся.
Эти же пакеты и ошибки видно в интерфейсе: «Цены» → «Лента скрипта».

| Код ошибки | Что не так | Что делать |
|---|---|---|
| `unknown_instrument` | бумаги нет в справочнике | загрузить бумагу в справочник, повторить |
| `future_time` | `time` снимка или конец бара позже текущего времени больше чем на 5 минут: бар ещё не закончился | проверить часы и часовой пояс; бар присылать после конца интервала |
| `misaligned_start` | начало бара не кратно его длине | выровнять `start` |
| `inconsistent_ohlc` | `high` или `low` противоречат `open` и `close` | проверить бар |
| `bad_timeframe` | длина бара больше 240 минут | использовать бары до 4 часов |
| `future_date` | дата ставки позже сегодняшней | проверить дату: нужна дата, за которую ставка |
| `duplicate_in_batch` | та же цена, тот же бар или та же ставка на ту же дату дважды в одном пакете | оставить одну запись |

Другие ответы:

| Код | Когда | Что делать |
|---|---|---|
| 401 | нет токена или он истёк | получить новый токен, повторить |
| 403 | у клиента нет роли `price_feed` | обратиться к администратору |
| 413 | пакет больше 5 МБ | разбить на части |
| 422 | пакет не проходит JSON Schema — не принято ничего | исправить формат; в ответе список ошибок |
| 503 | сервис временно недоступен | повторить через минуту |

## Повторная отправка

Ключ цены — бумага, источник, тип цены и `time`. Ключ бара — бумага,
источник, `timeframe` и `start`. Ключ ставки — `rate`, `date` и источник.
Пришло значение с тем же ключом — действует последнее полученное. Цены
и бары остаются в истории; у ставки хранится последнее значение.

Поэтому скрипт может:

- повторить пакет после ошибки сети или ответа 503 — дублей не будет;
- прислать исправление: тот же ключ с новым значением;
- дозагрузить историю: пакеты за прошлые дни принимаются так же.

Порядок пакетов неважен: время цены — в самой цене.

## Проверить пакет до отправки

```bash
uvx check-jsonschema --schemafile docs/api/price-feed/quotes.schema.json my-batch.json
```

Схема проверяет форму пакета. Есть ли бумага в справочнике и выровнен ли
бар, проверит только сервис.

## Пример на Python

```python
import datetime as dt

import requests

BASE = "http://localhost:8080"
CLIENT = {"client_id": "am-price-feed", "client_secret": "price-feed-dev"}
MSK = dt.timezone(dt.timedelta(hours=3))


def token() -> str:
    response = requests.post(
        f"{BASE}/auth/realms/am/protocol/openid-connect/token",
        data={"grant_type": "client_credentials", **CLIENT},
        timeout=10,
    )
    response.raise_for_status()
    return response.json()["access_token"]


def send_quotes(quotes: list[dict]) -> None:
    response = requests.post(
        f"{BASE}/api/marketdata/feed/v1/quotes",
        json={"source": "quik", "quotes": quotes},
        headers={"Authorization": f"Bearer {token()}"},
        timeout=30,
    )
    response.raise_for_status()
    for item in response.json()["rejected"]:
        print(f"отклонено: {item['code']} — {item['message']}")


now = dt.datetime.now(MSK).replace(second=0, microsecond=0).isoformat()
send_quotes([{"code": "SU26238RMFS4", "time": now, "vwap": 51.823, "bid": 51.784, "ask": 51.789}])
```

Токен живёт 5 минут. Если скрипт шлёт пакеты чаще, храните токен и берите
новый, когда старый истекает.

## Версии

Это версия 1 — она в адресе: `/feed/v1/`. Новые необязательные поля могут
появиться без смены версии; сервис их опишет здесь. Всё, что сломает
работающий скрипт, выйдет как `/feed/v2/`, а v1 продолжит работать, пока
скрипт не перейдёт.
