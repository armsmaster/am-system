# Открытые вопросы

У каждого вопроса — допущение, на котором идёт работа, пока нет ответа.
Ответ можно дать в чате или прямо здесь; принятый ответ переносится
в [decisions.md](decisions.md).

## Инструменты и методика

10. **Облигации.** Амортизация, колл-опционы эмитента (YTC), ОФЗ-ИН (ИПЦ)?
    *Допущение: амортизация и колл — да, ИПЦ — нет.*
11. **Справочные данные.** Купоны, оферты, амортизации — из MOEX ISS или из
    внешнего источника? *Допущение: адаптер ISS + ручная правка с версиями.*
12. **Конвенции.** Доходность — эффективная годовая, ACT/365? НКД — по
    биржевой формуле с округлением на одну бумагу до копейки, сумма сделки —
    от округлённого НКД? *Допущение: да, как у биржи, со сверкой с ISS.*
13. **Версия инструмента.** С какой даты действует — с публикации новых
    купонов или с даты оферты? Прошлые даты остаются на старой версии?
    *Допущение: с даты публикации; прошлые даты не пересчитываются.*
14. **Флоатеры: прогноз купонов.** Плоско по текущей ставке или по
    форвардной кривой? *Допущение: плоско (MVP); кривая — на втором этапе.*
15. **Реф. ставки и поправки.** Список ставок (КС, RUONIA, RUSFAR, …),
    механика каждой (среднее, сложный процент, лаг фиксации), базисы
    к RUSFAR. *Допущение: базисы — рыночные данные с историей.*
16. **Эталонные расчёты.** Excel на 2–3 бумаги каждого типа (фикс, оферта,
    флоатер на КС, флоатер на RUONIA, индексируемый номинал)
    с промежуточными шагами — станут тестами. *Ждём файлы.*
17. **РЕПО.** Виды (с ЦК: КСУ / конкретные бумаги; двустороннее; с ЦБ),
    направления, срок, дисконты, маржинальные требования, купон в период
    РЕПО. *Допущение: РЕПО с ЦК в обе стороны, фиксированная дата второй
    части.*
18. **Фьючерсы RUONIA** (второй этап). ВМ — поток по итогам вечернего
    клиринга, ГО — блокировка, оценка по расчётной цене? *Допущение: да.*
19. **OIS** (второй этап). Через ЦК или двусторонние? Источник котировок,
    сроки?
20. **БПИФ ДР.** Оценка по биржевой цене или по расчётной стоимости пая?
    *Допущение: по биржевой.*
21. **Комиссии от СЧА.** Виды, формула (СЧА какого дня, база дней,
    среднегодовая СЧА по правилам ДУ), выплата. *Допущение: ставка ×
    СЧА(D до начисления) / дней в году, выплата — накопленное начисление
    (корректировка — см. решение 43).*
22. **Финансовый результат.** FIFO или средняя? Разложение: курсовой,
    купонный, РЕПО, ВМ, комиссии? *Допущение: средняя, эти компоненты.*
23. **Метрики.** Модифицированная дюрация, DV01, выпуклость, спред-дюрация
    флоатеров, плечо, KRD? *Допущение: всё, кроме KRD, в MVP.*
24. **Цены.** Правило выбора цены (иерархия), лонг/шорт, DEMA (ряд, период),
    переоценка внутри дня? *Допущение: настраиваемая иерархия на класс
    инструмента с переопределением на бумагу; DEMA по дневным; текущий
    день — по последним доступным ценам.*

## Процессы и роли

25. **Трейдинг и сопровождение.** Кто вводит и подтверждает сделки, кто
    ведёт справочники, операции, ручные рыночные данные? Нужны ли «четыре
    глаза»? *Допущение: трейдинг вводит сделки и ручные рыночные данные;
    сопровождение подтверждает сделки, ведёт операции и справочник
    инструментов.*
26. **Лимиты.** Виды; мониторинг или блокировка; проверка «что если».
    *Допущение: мониторинг после сделки + уведомление в UI; pre-trade —
    позже.*
27. **Импорт JSON.** Наш формат или выгрузка внешней системы? Есть ли
    биржевой номер сделки? *Допущение: свой формат, обязательный внешний
    ID.*

## Уточнения по ответам

50. **Паи в операции.** Пользователь вводит и сумму, и количество паёв
    (а мы суммируем количество) или только сумму, а количество вычисляется
    от нашей расчётной стоимости пая? *Допущение: вводятся оба числа;
    количество — с 5 знаками после запятой.*
51. **Ручное подтверждение расчёта.** Только для операций с паями?
    *Допущение: да; сделки исполняются автоматически в плановую дату,
    неисполнение ловит сверка; у операции с паями есть плановая дата для
    лестницы; частичного расчёта нет.*
52. **Формат приёмника остатков.** *Допущение: свой JSON (счёт, дата,
    остатки бумаг, остаток денег) по API с токеном источника и через ручную
    форму; исходный файл хранится вложением.*
53. **Облако.** Провайдер? Управляемый PostgreSQL? *Допущение: да; сервисы
    и Keycloak — в контейнерах на ВМ под compose.*
54. **Доступ пользователей.** VPN или интернет (TLS + Keycloak)? OTP?
    *Допущение: интернет по TLS, OTP обязателен для всех.*
55. **Источник 1000 сделок в день.** Что выгружает сделки (QUIK, система
    брокера)? От этого зависят требования к импорту.
